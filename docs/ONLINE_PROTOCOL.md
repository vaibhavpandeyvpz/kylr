# Online protocol: HTTP v1 / ENet v2

All public API paths start `/v1`; JSON errors carry `{error: {code, message}}`. Access JWTs use HS256 with fixed issuer `kylr`, audience `kylr-client`, required `sub`, `sid`, `exp`, `iat`, and a 15-minute lifetime. Refresh tokens rotate atomically within a maximum 30-day session; logout revokes that session and existing access JWTs. Credentials travel only in bodies or Authorization headers. Production API traffic uses TLS.

| Method/path | Request | Response |
|---|---|---|
| POST `/accounts` | username, password, display_name | access_token, refresh_token, expires_at, player |
| POST `/sessions` | username, password | same session envelope |
| POST `/sessions/refresh` | refresh_token | rotated session envelope |
| DELETE `/sessions` | Bearer JWT | revoked |
| GET `/me` | Bearer JWT | player |
| PUT `/me/loadout` | head, emote, primary, secondary stable IDs | server-validated player |
| POST `/matches` | type: DM/TDM/CTF/ELIMINATION/GUNGAME; Bearer JWT | request_id, state, timeout_seconds |
| GET `/matches/{request_id}` | owning session JWT | Searching / Starting server / Ready / Failed, connection assignment when Ready |
| DELETE `/matches/{request_id}` | owning session JWT | cancellation and reservation release |

Private server-control routes require `X-Control-Token`. Edgegap instances use an independent server-bound credential, with only its hash stored by the API; the local stack uses its configured control secret. `/internal/servers/{server_id}/heartbeat` sends match_id, phase, admitted account IDs; `/admit` sends match_id and opaque ticket; `/release` sends reservation_id. Heartbeats renew a 15-second health lease. Reservations/tickets expire after 30 seconds. A heartbeat confirms each newly admitted slot before absence can remove it; an unconfirmed admission has a 30-second grace window so asset loading cannot make an older heartbeat revoke it. Admission atomically changes the matching unused ticket's state in the same MongoDB server document that enforces ten slots. A wrong server/match, expired/replayed ticket, revoked session, finished match or unhealthy server rejects admission. Empty instances retire after 60 seconds.

The ENet protocol sends inputs, not claimed positions, damage, kills or scores. The authenticated peer-to-account binding supplies identity. Server snapshots include a protocol version, match generation, acknowledged input sequence, roster/appearance, map/phase/clock, score-reaching times, pickups/repair timers, flags, arena event phase and projectile state. Generation and monotonic sequence checks reject stale traffic. Initial reliable snapshots precede control; movement updates are sequenced, while admission/roster/results transitions are reliable. Client movement prediction uses the shared physical controller, replays unacknowledged commands after reconciliation, and interpolates remote presentation. The server alone accepts combat and objective events.

# Local implementation and verification

Public deployment uses [Render, Atlas and Edgegap](CLOUD_HOSTING.md). The following stack is for local development. Run `tools/start_online.ps1 -Build` from the game repository to build the Godot server image and start MongoDB and Flask/Waitress. The launcher generates separate local signing/control secrets under ignored `reports/online/local.env`. API and published game ports bind to loopback. Docker's API network alias is `account-api`; Godot's HTTP client rejects a hostname as short as `api`. The local API scheduler mounts the Docker socket and controls only containers it creates. This configuration is not a public deployment design.

If Docker/WSL is unavailable, `services/.venv/Scripts/python.exe tools/start_online_native.py` provides a Windows fallback. It downloads the official MongoDB 8.0.20 ZIP with SHA-256 verification into ignored reports, starts MongoDB on loopback, and starts the same API with a native Godot scheduler. It does not install a Windows service. Stop that owned fallback before starting Docker on the same ports. Account databases in the native directory and Docker volume are separate.

The client reads `network/services/api_url`, falling back to `http://127.0.0.1:8080`; `KYLR_API_URL` overrides it for local tests. Public builds use an HTTPS API origin. Requests allow 75 seconds for Render cold starts, and matchmaking uses the backend's advertised `timeout_seconds` plus a 15-second response margin (180 + 15 seconds by default, up to a 600-second server budget). Passwords and access tokens stay in memory. On Windows the rotating refresh credential is stored using CurrentUser DPAPI, bound to the API endpoint, through a hidden helper with stdin/stdout pipes. Only ciphertext is written to `user://online-session.bin`; other platforms currently retain the session only in memory. No credentials are saved in preferences or command-line arguments.

Both ENet peers mount `OnlineTransport` at `/root/OnlineTransport`. Server simulation uses the existing match/combat/arena controllers, with human-only rosters. Commands carry a generation and monotonically increasing sequence, normalized movement, bounded finite aim, boolean actions and owned slot selectors. Position, damage, inventory, name and team are never accepted from input packets. Authentication, input rate, queue length and stale input are checked before simulation. The input payload uses bounded DEFLATE decoding; unauthenticated peers cannot feed its decoder.

Inputs run at the 60 Hz physics tick, with six recent commands repeated for loss recovery. The server drains each bounded input burst in order, applies discrete actions, and simulates only the latest held movement intent once per physics tick; extra packets never grant extra movement. The server acknowledges commands after the simulation tick and broadcasts snapshots at 20 Hz. Compressed snapshots are split into payloads of at most 1,000 bytes, assembled with bounded buffers, and older incomplete snapshots are discarded. Initial admission, roster/phase transitions and round replacement use reliable complete snapshots. After 500 ms without a complete snapshot, a client requests a reliable resynchronization, limited to once per second on both peers; this recovers incomplete UDP snapshot bursts without accepting client authority. Remote robots interpolate presentation over 100 ms. Local movement restores the authoritative motor and replays at most the latest 15 unacknowledged commands (250 ms) through the same movement function; speculative fire only plays presentation and cannot change ammo, damage or score. Hits are evaluated at the current server simulation tick.

Snapshot state includes map, generation, clock, goal, team totals/reaching times, account appearance, robot resources/inventory/motor/repair/protection, fixture availability and machinery channels, arena events, flags, projectiles, corpses, energy drops, feed, captions and results. Late join restores these before exposing local control. Session revocation is checked on heartbeat; disconnect removes the actor, drops objectives, aborts repair and recalculates the target. Active DM or Gun Game with fewer than two players, or team games with an empty team, cancels without automatic continuation. Active Elimination rejects new reservations and admissions and retains its starting goal; eliminated robots spectate. Reliable result captions carry winner IDs so private victory speech does not depend on final-snapshot arrival order. Fall credit is resolved on the server from accepted damage, never client identity input; its kill feed retains both the qualifying weapon and fall cause. A normal finish retains participants and replaces the round after 15 seconds. Faceoff and Skyfall are eligible; round replacement selects a different map. Countdown and next-round rosters are also validated. Canceled results return to the lobby after three seconds, retaining an explanatory reason.

Verification entry points: `python -m pytest services/tests` (set `MONGO_TEST_URI` to cover atomic multi-slot updates on real MongoDB; test doubles do not qualify admission), `tools/verify_online.py --mongo mongodb://127.0.0.1:27017` (three native Godot processes and real HTTP/MongoDB), `tools/verify_online_docker.py` (production matchmaking/scheduler and Docker-hosted games), `tools/probe_online_credentials.gd`, and `tools/probe_online_ui.gd` (rendered account/customization flow). Reports contain test results and screenshots, never passwords, bearer credentials or admission tickets.

For Python verification, create `services/.venv` using `python -m venv services/.venv`, then install `services/requirements-dev.txt` with its Python interpreter. The Docker launcher needs Docker Desktop's Linux engine; it installs backend dependencies inside the API image. Stop the local stack with `docker compose --env-file reports/online/local.env -f services/deploy/compose.yaml down`; the MongoDB volume retains accounts.

Prediction history is bounded to 120 commands. At that limit, the client pauses speculative advancement and resends pending intent while reliable resynchronization catches up; an eight-second silence deadline handles a lost server. Reconciliation runs physical movement without repeating footsteps, landing cues or animation events.

## ENet v2 accepted presentation and lifecycle

ENet v2 requires matching client/server builds. HTTP remains v1. Automatic peer relay is disabled: authenticated clients communicate only with the authoritative server.

Spawn reload presentation includes its remaining time and duration in robot snapshots. Clients seek the authored pistol reload to that progress, including late joins, without changing the ammunition reload timer or spawn protection.

Complete reliable snapshots use the same bounded compressed representation as periodic snapshots (64 KB compressed / 256 KB decoded). Presentation channel 3 reliably delivers accepted discrete shots, damage feedback, projectile contacts (including the lightning orbÃ¢â‚¬â„¢s discrete `electric` burst), explosions, EMP, world cues and raw callout events. Shot counters deduplicate reports independently of snapshot sequence. Local prediction can suppress its immediately confirmed shot presentation, but cannot award a hit. Streaming contact, grounded movement and stride state travel in snapshots; remote sounds use the listener's actual local robot, rather than the actor's human flag.

Only global critical captions are restored from snapshots. Ordinary captions are filtered per recipient for range, direction and frequency on the receiving client. Flag animation phase, repair occupants, corpses and machinery are restored before control. Remote deaths extinguish authored emission; respawn restores it. Client/server crouch capsules both use 1.18 m height.

Packet bursts use a token bucket (360 burst, 120 packets/s refill); input queues remain bounded and never grant extra movement ticks. Heartbeat health leases and the 15-second continuation use wall time. Graceful departure and revoked reservations immediately remove the authoritative actor, drop flags and abort repair. Disconnected ENet peers receive no further snapshots. Rendering preferences explicitly reach online matches mounted beside the app, and temporary views never overwrite the saved camera choice.

Completed snapshots are coalesced to the newest monotonic snapshot and applied once per client physics tick. Reliable presentation events flush after that state update, so a snapshot cannot erase an accepted hit marker in the same tick. Unchanged fixture transforms and animation positions are skipped. The server logs the map-selection seed, selected map, previous map and mode for each generation.

Online round replacement first sends a reliable loading notice. Clients suspend
input prediction and use a bounded 90-second loading deadline rather than the
normal eight-second snapshot-silence deadline. The server continues authenticated
heartbeats in a non-admitting phase while asynchronously populating the next map.
Human-only online rounds skip bot traversal-graph generation.
